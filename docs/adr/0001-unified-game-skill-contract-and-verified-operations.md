# ADR-0001: Unify the game-skill contract while exposing only verified operations

- Status: Accepted
- Date: 2026-08-30

## Context

The Arknights skill has a complete selection lifecycle: independent valuation dimensions, run-only preference weighting, verified dual-platform operations, raw run artifacts, deterministic finalization, provenance, self-improvement, and delivery gates. The other game skills have uneven evaluation and query capabilities. Treating their shallow sample validators as equivalent hides real gaps; duplicating unverified live browser routes would create false confidence.

The repository is also removing every legacy query path in favor of `ego-ops` operations executed through `ego-browser`.

## Decision

All game skills adopt one capability contract for valuation, reusable evaluation, raw-artifact finalization, provenance, self-improvement, delivery, and evaluator enforcement.

Live query support remains capability-based. A platform/game/list-or-detail route is exposed only when its `ego-ops` operation has been observed and validated with `ego-browser`. The toolkit publishes an operation support matrix. Unsupported combinations fail closed and do not fall back to another browser tool.

The public verification seams are:

1. Offline game-specific sample and trap regressions.
2. Raw run-artifact finalizer, sidecar, quality-gate, and delivery-contract regressions.
3. Toolkit `ego-ops` manifest/query-stack validation plus real smoke checks for operations that are already supported.

## Consequences

- The four game skills can be evaluated against the same meaningful contract without pretending that all platforms expose identical data.
- New game skills generated by the repository must include reusable evaluator and finalizer interfaces, not only a sample script.
- Platform coverage grows through verified operation additions rather than browser fallback code.
- Evaluator scores may initially fall as shallow checks are replaced with contract enforcement; passing scores become stronger evidence.
