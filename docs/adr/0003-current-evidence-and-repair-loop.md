# ADR 0003: 当前知识、账号字段和可回滚改进

状态：accepted，2026-10-05。用户确认以明日方舟先完成、25分钟左右交付、缺关键字段进入待核实、授权有证据的自动估值修复。

## 决策

1. `community-evidence.json` 保存逐主张来源；Markdown是审阅副本。日期、玩法、版本、作者独立性和冲突决定主张是否参与当前评分。历史知识保留基础获取事实和候选探索价值，不能靠刷新文件日期获得当前资格。
2. 主线活动、肉鸽、高难分别计算；多个玩法取最低实战项并展示各项。当前第一版沿用共有职能分类，不宣称已完成各肉鸽主题与高难关卡专门模型。
3. `field_evidence` 绑定账号、URL、时间、结构化原字段或图像区域。关键字段由请求和推荐主张决定，未知字段保留 null；相互矛盾的证据不能默默择一。
4. 新 runner 的 evidence_policy v1 由 finalizer 强制重算推荐资格。旧 fixtures/旧产物保持原确定性契约用于回归，不能将旧离线成功当当前真实推荐通过。
5. 查询保存 checkpoint、原观察时间、操作次数和截止时间。Agent先交付可核实结果，再在同一会话处理有授权的修复清单。脚本不生成模型补丁，不启动后台自治。
6. 改进保存内容寻址基线、保护既有测试、固定运行门禁，并绑定当前源码。回滚只作用完整声明的责任文件，拒绝覆盖后续修改。估值事实改动额外核查来源，人的审阅仍负责适用性和真实体验。
7. 本机 ego-ops 没有操作文件时允许读取仓库随附的实测副本，解决不同机器经验缺失。外部显式目录或已有漂移文件不使用补齐；逐次页面身份、编号、信号与字段验证仍执行。

## 取舍和验收边界

严格证据门槛会暂时减少主推荐，这是可见的待核实状态；修复必须继续补查，不把“全部挡住”报告为推荐质量已经提升。7天来源窗口保守，长期稳定机制可单独作为官方事实维护，不能伪造发表时间。

此次真实来源表明联动名单从25增到29、精二总数与精二六星不同、详情读取存在渲染竞态。两份10月1日社区简介还不足以证明逐玩法阵容，故不发布新的强度权重。用户对3–5个真实样本的事实、理由和排名认可另行记录，机器通过不替代该验收。
