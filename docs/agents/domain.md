# Domain docs

This repository uses a single domain context.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant architecture decisions under `docs/adr/` when they exist.
- If either location is absent, proceed silently. The domain-modeling workflow creates documentation when terminology or an important decision is actually resolved.

## Vocabulary

Use the canonical terms defined in `CONTEXT.md` in specifications, issue titles, tests, and implementation. If a needed concept is missing, first decide whether it is a real domain gap or an unnecessary synonym.

## Architecture decisions

If proposed work conflicts with an existing ADR, surface that conflict explicitly instead of silently overriding the decision.
