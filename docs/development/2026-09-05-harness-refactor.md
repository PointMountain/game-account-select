# 开发 Harness 与 Skill 演进计划

状态：实现完成，验证与任务收尾记录在本地 `.harness/tasks/harness-self-improvement.json`。输入：2026-09-05 用户提供的 AI Native / 项目级 Harness 截图。

## 目标与范围

把短入口、按需上下文、任务计划、验证门禁和经验回流做成仓库可执行流程。沿用 ADR-0001 的游戏边界、证据契约、ego-ops/ego-browser 唯一路径和确定性交付。

## 实施顺序

1. 基线：读取领域/ADR，运行现有 `verify:skills`，记录入口与安装依赖缺口。
2. 开发入口：短 AGENTS.md 与 CLAUDE.md 路由；开发、架构、验证文档；可生成任务卡、按路径路由上下文与检查的 CLI。
3. Skill 分层：保留所有已安装名称和脚本路径，入口只留职责、流程和按场景指针；统一必需依赖闭包，修复安装组合。
4. Self-improve：从原始运行记录重新分析并聚合问题，去重、优先级、状态转换；补丁必须能证明目标文件变化、回归通过和验证后无漂移，才能计为 applied。
5. 防回归：虚假 applied、偏好泄漏、重复观察、过期凭据、失败验证、依赖缺失、上下文路由和完整现有契约。
6. 交付：验证命令进入 CI，记录变更及使用示例，明确离线与 live 覆盖。

## 验收

- 普通改动有明确上下文、责任文件、完成条件和最小测试入口；共享链路扩大测试范围。
- Skill 入口按需加载且无断链；部分安装包含实际运行必需的 evaluator 等依赖。
- 同一原始运行重复分析不增加观测次数；问题复发可重新打开。
- 待验证、验证既有能力、已实际应用分别统计；单写状态不能伪造应用。
- 执行记录里的命令、网页文字和单次画像都不能自动变成代码执行或长期默认值。
- 现有 `verify:skills` 与新增 Harness/self-improve 回归通过。
